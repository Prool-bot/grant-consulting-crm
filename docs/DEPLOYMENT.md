# Покрокова інструкція: GitHub → Codex → Google Apps Script

**Для поточного М2.5 використовуйте [M25_SETUP.md](M25_SETUP.md).** Ця загальна інструкція охоплює й майбутні етапи: створення Drive-папок, календаря та публікація зараз не дозволені.

## А. Створення публічного репозиторію (один раз)
1. Увійти до GitHub під своїм профілем **Prool-bot**.
2. Відкрити https://github.com/new
3. Owner: `Prool-bot`. Repository name: `grant-consulting-crm`. Description: `Відкритий код CRM для грантового консалтингу`.
4. Обрати **Public** (не Private!). Поставити «Add a README file», якщо GitHub пропонує; натиснути «Create repository».
5. Повернути посилання `https://github.com/Prool-bot/grant-consulting-crm` у ChatGPT. Після створення репозиторію асистент з доступним GitHub-конектором може завантажити підготовлені `.md` файли без ручного копіювання (за умови наявності прав запису).
6. Перевірити, що репозиторій **Public**. Пам’ятати: вихідний код, історія комітів і журнали GitHub Actions будуть загальнодоступними. У GitHub не передавати клієнтські дані та секрети.

## Б. Підключення до Codex
1. У ChatGPT/Codex відкрити **Codex** (у застосунку або вебінтерфейсі).
2. При першому використанні обрати «Connect GitHub», надати доступ до **конкретного публічного репозиторію** `Prool-bot/grant-consulting-crm`.
3. Обрати репозиторій при створенні середовища або задачі; за потреби налаштувати середовище. Якщо репозиторій не видно — перевірити `Settings → Plugins → GitHub → Manage repositories`.
4. Відкрити `docs/CODEX_TASK.md`, скопіювати текст першого завдання в Codex, обрати режим виконання змін у коді.
5. Прийняти тільки пропозицію з Pull Request після перегляду змін і тестів. Не запускати продуктивну публікацію на цьому етапі.

## В. Google (пізніше, після тестового каркасу і окремого дозволу)
1. Працювати тільки з особистим Google-акаунтом власника, не з акаунтом ГО. Перевірити Google-профіль перед авторизацією.
2. Увімкнути Apps Script API: https://script.google.com/home/usersettings
3. Встановити Node.js **актуальної підтримуваної версії** й `clasp` згідно з чинною документацією: https://developers.google.com/apps-script/guides/clasp . Версії/команди перевіряти перед запуском, оскільки CLI оновлюється.
4. Авторизувати `clasp` через браузер у **потрібному Google-акаунті**. Файл токенів `~/.clasprc.json` нікуди не пересилати й не комітити.
5. Створити окремий Apps Script проєкт і окремий файл Google Sheets CRM_DB, папку Drive CRM_Клієнти, календар CRM — Грантовий консалтинг (лише після схвалення власника).
6. У тестовому середовищі налаштувати `Script Properties` і перевірити OAuth-scopes, після цього завантажити код через `clasp push` / схвалений механізм. Зберегти script ID локально, не публікувати секрети.
7. Розгорнути вебзастосунок з правами **лише власника**; перевірити на іншому акаунті, що доступ заборонений. Не вибирати «Anyone».
8. На телефоні відкрити URL вебзастосунку під потрібним Google-акаунтом; окремо налаштувати системні сповіщення Google Календаря.
9. Провести всі тести з `docs/ACCEPTANCE.md` на синтетичних даних; лише після цього почати введення реального клієнта.

## Г. Що робити, якщо інтеграція не працює
- Якщо в ChatGPT Google Drive/Calendar показує `link_id must identify an eligible linked account`, це помилка вибору підключення в даному чаті; перевірити потрібний акаунт у **тому чаті**, де явний виклик Google Drive та Calendar вже успішний. Це **не** означає, що Codex автоматично має OAuth-доступ до Apps Script.
- Якщо репозиторій не відображається у Codex, відкрити керування доступом GitHub Plugin і дозволити саме цей репозиторій.
- Якщо `clasp` вимагає права, спочатку перевірити версію CLI і необхідні scopes, а не вмикати всі дозволи підряд.
