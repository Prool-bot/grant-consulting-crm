# CRM 1.4 — заключне приймання вебінтерфейсу в браузері (тільки staging)

Дата: 05.11.2026. Стан: **підготовлено; ручне браузерне підтвердження ще не отримано**.

## Межа безпеки

- Відкривати **лише той самий окремий тестовий Apps Script CRM 1.4**, в якому успішно виконано `verifyCrmIsolatedCalendarSync()`. Не відкривати і не змінювати робочу CRM 1.3.
- До Apps Script було завантажено HEAD коміту `637e9e4` через staging CI. Для перегляду не потрібні нове versioned deployment, production `clasp push`, merge чи зміна Script Properties.
- У власному акаунті Google відкрити **Розгорнути (Deploy) → Тестові розгортання (Test deployments)**; за потреби в полі типу вибрати **Вебзастосунок (Web app)**. Скористатися наданим Google URL, що закінчується **`/dev`**. Цей URL працює з поточним кодом HEAD тільки для редакторів цього Script. **Не вибирати «Нове розгортання»**.
- У `CRM_1_4_TEST_DB` можуть існувати дані, синтетичність яких не підтверджено. У браузерному прийманні **нічого не створювати, не редагувати, не видаляти, не натискати синхронізацію Calendar**. Не надсилати URL, дані клієнтів, e-mail чи незафарбовані скриншоти до GitHub/чату.

## Один безпечний ручний сценарій (читання/навігація)

1. Відкрити тестовий URL **`/dev`** в тому самому Google-акаунті власника. Підтвердити, що сторінка завантажила «Каталог клієнтів», а не «CRM недоступна» чи «Доступ закрито».
2. Відкрити пункт **«Клієнти»**. Переконатися, що видно таблицю з заголовками, пошук та «Розширені фільтри». Ввести завідомо вигаданий пошуковий запит (не додає запис), перевірити порожній результат, очистити пошук. Відкрити/закрити панель фільтрів. За потреби випробувати сортування.
3. Якщо є тестовий клієнт, відкрити його картку й послідовно переключити вкладки **«Огляд», «Досьє», «Контакти», «Історія», «Заявки», «Документи», «Партнери»**. Не ділитися жодним вмістом картки. Якщо немає клієнтів, перевірити лише сам реєстр і повідомити «картку не перевірено».
4. Відкрити **«Реєстр заявок»**, повернутися до «Клієнтів». Оновити **саме сторінку `/dev`** у браузері і впевнитися, що сторінка знову завантажується без помилок. На цьому завершити; кнопки «Зберегти», «Видалити», «Синхронізувати», «Створити клієнта з партнера» **не натискати**.

## Приймальні критерії

- Усі зазначені read-only екрани й навігація працюють, після оновлення немає помилки автентифікації чи помилки CRM.
- Немає мутацій у `CRM_1_4_TEST_DB` чи нових подій Google Calendar від браузерного тесту.
- Окремий автоматизований CI перевіряє `doGet()` для авторизованого та неавторизованого власника, відсутність відкриття Sheets / Calendar на HTTP entry point, приватний manifest і браузерні маршрути. **Автотести не замінюють ручного браузерного приймання.**
- Звіт власника до PR: лише `CRM_UI_BROWSER_OK` або `CRM_UI_BROWSER_FAILED` з коротким описом кроку, без URL, ID, реєстраційних даних чи клієнтських записів.

Якщо `/dev` недоступний: **не** змінювати production deployment або права доступу. Передати лише текст помилки (без приватних деталей) для діагностики. Після успішної перевірки лишиться етап приватної резервної копії production та тестового відновлення на **окремій копії**, плюс окреме рішення про випуск.
