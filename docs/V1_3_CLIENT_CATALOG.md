# CRM 1.3 — перевірка каталогу клієнтів

Реалізовано всі вісім пунктів: компактні 11 колонок із широкою назвою; соцмережі в досьє; код неприбутковості; Подано/Отримано; дата реєстрації та повні роки; чотири нові типи; редагування примітки в клітинці; дворядкові напрями.

Сумісність: JSON існуючих клієнтів, незмінні PROFILE, модель 12 та схема 2. Без нових залежностей, зовнішніх API чи OAuth scopes. Робоча Google Sheets, Apps Script, Netlify й розгортання не змінювалися. Правила розрахунків: [DATA_MODEL.md](DATA_MODEL.md).

Автоматична перевірка: `npm test`, `npm run build`, `node scripts/verify-cloud-release.js`. Новий `tests/crm13.test.js` охоплює всі вісім вимог, 25 клієнтів, числове сортування, XSS/URL, високосні дати, конфлікт/подвійне натискання, старі та нові snapshots, normalize/restore і збереження профілів. Чинні тести додатково перевіряють квоти, збої запису, журнал, повтори RPC та ревізії.

## Ручна перевірка на окремій копії

Виконувати власнику лише після окремого дозволу на тестове Google-середовище. У межах цього PR жодних Google-операцій не виконано. OAuth — наявний доступ до Sheets; нові дозволи не потрібні. Доступ лише MYSELF, виконання USER_ACCESSING; зберегти CRM_OWNER_EMAIL і CRM_ENABLED приватними.

1. Використати окрему тестову копію бази CRM 1.2 із вигаданими даними та окремий тестовий Apps Script. Не змінювати продуктивні ID, файли чи `/exec`. Зберегти незалежну резервну копію.
2. Відкрити каталог на 1440 і 360 px: назва 300–380 px, горизонтальна прокрутка лише таблиці, повна юридична назва з ГО. Напрями максимум два рядки, повний текст у title та картці.
3. Створити понад 20 вигаданих клієнтів; перевірити сторінки, пошук, кожен новий тип у формі й фільтрі. Переконатися, що старі контакти, заявки та ЄДРПОУ незмінні.
4. У досьє зберегти `0032`, сьогоднішню дату, дату 29.02.2020; майбутню дату й неправильний код відхилити. Для фізособи вік не показується.
5. Додати кілька соцмереж, видалити один рядок, зберегти й повторно відкрити. Перевірити додавання/видалення після повторного відкриття. Небезпечний URL відхиляється; посилання показують назви платформ.
6. Створити заявки: чернетка із сумою, submitted, won без суми, rejected в архіві, stopped без дати й із датою, видалену won. Перевірити лічильники й сортування 2/10, не прирівнювати виграш до платежу.
7. Ввести примітку, змінити фільтр і повернутись; текст лишається. Зберегти та скасувати окремо. В іншій вкладці змінити клієнта: застарілий запис відхиляється, текст примітки залишається; скопіювати його перед оновленням. Під час обриву повторити початковий запис через чинний механізм без дубля.
8. Перевірити відновлення резервної копії лише в тестовому середовищі, зв’язки та журнал. Перед будь-яким майбутнім продуктивним випуском виконати [ACCEPTANCE.md](ACCEPTANCE.md) та ручний огляд безпеки.

Локальна перевірка 21.10.2026: 99/99 тестів пройдено; збірка й verify-cloud-release успішні. У браузері перевірено 1440×900 (назва приблизно 352 px, ширина сторінки 1440 px) та 360×800 (ширина документа 345 px за наявності вертикального скролбару): горизонтального переповнення сторінки немає. Перевірено примітку після фільтрації, екранування HTML як тексту, збереження 0032/29.02.2020, додавання та видалення соцмереж після повторного відкриття. Google-приймання залишається ручним кроком на окремій копії.

Оптимізація швидкості в цьому ж PR: [контракт, вимірювання до/після та перевірки](V1_3_PERFORMANCE.md). Один bootstrap замість послідовних RPC, дельти після записів; повні перевірки цілісності залишаються.
