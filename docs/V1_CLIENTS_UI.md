# CRM 1.0 — інтерфейс клієнтів

Оновлення від 13.10.2026. Реальні Google-ресурси та чинне розгортання не змінювалися. Нових бібліотек у CRM, платних компонентів і ШІ немає.

## Інтерфейс

- «Клієнти»: компактна таблиця із сімома колонками, пошуком, сортуванням кожної колонки в обох напрямках і сторінками по 20 записів. Фільтри типу та статусу приховані при відкритті; є скидання і лічильник активних фільтрів.
- Географія в таблиці — наявне `location`; географія роботи `geography` залишається в досьє й бере участь у пошуку. Кількість заявок включає архівні та виключає м’яко видалені.
- Посилання з каталогу та грантового реєстру відкривають картку в режимі перегляду. Збережено адреси `#profile/<id>`.
- «Огляд»: назва, тип, статус, місце розташування, напрями діяльності. Створення клієнта містить лише ці п’ять полів.
- «Досьє»: розширені відомості, реквізити, пріоритет, джерело, наступна дія, досвід і потреби. Основні поля тут не дублюються.
- «Контакти», «Історія» та «Заявки»: відповідні наявні пов’язані записи. Форми додавання контакту/взаємодії відкриваються окремими кнопками; історія залишається незмінною після додавання.
- Кнопка «Редагувати» відкриває форму поточної вкладки «Огляд» або «Досьє». «Скасувати» повертає перегляд без запису; успішне збереження повертає перегляд тієї ж вкладки.
- Окремий пункт «Досьє» вилучено з меню; у картці активним залишається пункт «Клієнти».

## Сумісність і дозволи

Використано наявні клієнти, `client_profiles`, контакти, взаємодії та заявки. Схема/версія Google Sheets не змінена, міграція не потрібна. Часткове збереження вкладки передає обов’язкові поля для чинної валідації; сервіс зберігає решту старих полів, UUID, номер і зв’язки. Лічильник заявок обчислюється лише для відображення.

OAuth без змін: `spreadsheets` для наявного сховища, `userinfo.email` для перевірки власника. Локальні перевірки не використовують Google OAuth. Доступ збірки залишається `MYSELF` / `USER_ACCESSING`.

## Перевірки

`npm test`: 57 успішних тестів, включно з новими перевірками семи сортувань, пошуку географії/номера, архівних і видалених заявок, часткового редагування, старих полів профілю та незмінності заголовків Sheets. Наявні перевірки квот, конфліктів, повторів запитів, часткових записів, резервних знімків/відновлення та календарного fake також успішні.

`npm run build`: автономна збірка Apps Script; синтаксис вбудованих скриптів і приватний маніфест перевірено тестами.

`scripts/check-clients-ui.cjs`: окремий браузерний сценарій, виконаний з уже наявним у середовищі Playwright і Edge, без встановлення пакетів у проєкт. Скрипт сам піднімає локальний сервер на 4175, використовує новий ізольований профіль браузера та закриває їх після перевірок. Якщо Playwright уже доступний через `NODE_PATH`, запуск: `node scripts/check-clients-ui.cjs`. Не входить у `npm test`, яке залишається без зовнішніх залежностей. `CRM_SCREENSHOTS` — необов’язкова локальна папка для знімків синтетичної демонстрації.

Перевірено таблицю, приховані фільтри, пошук/сортування, режим перегляду, збереження огляду й досьє, контакти/історію, створення клієнта та заявки, архів/відновлення й м’яке видалення. Ширини 1440×1000 та 360×800; горизонтального переповнення сторінки немає, прокручується таблиця. Скриншоти каталогу й картки переглянуто; помилок JavaScript немає.

## Передавання збірки

Готові файли: `dist/apps-script/Code.gs`, `Server.gs`, `Index.html`, `appsscript.json`. Оновлювати код і розгортання можна окремим рішенням власника за [V1_DEPLOYMENT.md](V1_DEPLOYMENT.md). Для цього оновлення повторна ініціалізація бази не потрібна. Перед продуктивним запуском залишаються фактична перевірка Google-входу, ручний огляд безпеки та `ACCEPTANCE.md`.
