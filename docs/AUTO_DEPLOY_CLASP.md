# Безкоштовне кероване оновлення CRM через GitHub Actions + clasp

**Статус після додавання файлів:** автоматизація налаштована в репозиторії, але **розгортання не запускається**, доки власник не додасть свої три приватні GitHub Secrets, не увімкне Apps Script API та не натисне `Run workflow`. Жодних публічних ключів чи реальних клієнтських даних у GitHub.

## Умови

- Використовувати **виключно** особистий Google-акаунт власника, визначений у приватних налаштуваннях CRM.
- Застосунок Apps Script та `CRM_DB_TEST` уже існують. **Не створювати нові ресурси**.
- Спочатку зберегти резервну копію Google Sheets і перевірити обмеження доступу.
- Нова версія сторінки «Клієнти» поки є в локальній збірці Codex/ZIP. **Перед запуском GitHub Actions потрібно внести й об’єднати оновлені вихідні файли в `main`.** Інакше Actions зібрав би старий інтерфейс; скрипт перевірки зупинить таку спробу.

## Одноразове налаштування Google на вашому комп'ютері

1. Відкрити `https://script.google.com/home/usersettings` під **особистим Google-акаунтом власника CRM** і ввімкнути **Google Apps Script API**.
2. У Windows PowerShell (Node.js 22+):
   ```powershell
   npm install -g @google/clasp@3.4.1
   clasp login
   ```
   Авторизувати тільки **особистим Google-акаунтом власника CRM**. `clasp login` створює **приватний** файл `%USERPROFILE%\.clasprc.json` — це OAuth-токени. **Нікому не надсилати цей файл, зокрема ChatGPT, не завантажувати його в GitHub і не вкладати в архів із кодом.**
3. В Apps Script → **Налаштування проєкту** скопіювати **Ідентифікатор сценарію (Script ID)**. Це **не** ID таблиці `CRM_DB_TEST`.
4. У **Ввести в дію → Керувати розгортаннями → активний вебзастосунок** скопіювати **Deployment ID**. Він відрізняється від Script ID. Перевірити, що доступ — **Only myself** і виконання — **User accessing**.

## Одноразове налаштування GitHub

Відкрити `Prool-bot/grant-consulting-crm` → **Settings → Secrets and variables → Actions → New repository secret**. Створити **три секрети**:

| Назва секрету | Значення |
|---|---|
| `CRM_SCRIPT_ID` | Script ID чинного проєкту «Каталог клієнтів CRM» |
| `CRM_DEPLOYMENT_ID` | Deployment ID чинного вебзастосунку (щоб URL залишився незмінним) |
| `CLASPRC_JSON` | Повний JSON із **локального** `%USERPROFILE%\.clasprc.json` після `clasp login` |

**Увага, ризик:** `CLASPRC_JSON` містить чинні облікові дані для Google API. GitHub Secrets їх шифрують для зберігання, але код GitHub Actions має доступ до них під час ручного запуску. У публічному репозиторії **обов'язково перевіряти кожен Pull Request перед об'єднанням з `main`**, особливо зміни в `.github/workflows/`, `scripts/` та JavaScript, який виконується під час збірки. Після підозрілої активності потрібно відкликати авторизацію clasp у Google та замінити секрет. Якщо зберігання Google OAuth-токенів у GitHub небажане, використовуйте **локальне оновлення** `scripts/deploy-crm-local.ps1` (токени залишаються на вашому ПК).

За бажанням у **Settings → Environments** можна створити `production` і налаштувати захист. Одна лише наявність назви `production` у файлі workflow **не вмикає** обов'язкове ручне погодження середовища; окреме підтвердження вже передбачене в `Run workflow`.

## Оновлення CRM (після налаштування)

1. Усі зміни Codex спочатку перевірити локально та зберегти в GitHub через Pull Request; об'єднати перевірені зміни в `main`.
2. Відкрити GitHub → **Actions → CRM — ручний випуск у Google Apps Script → Run workflow**.
3. Вибрати гілку **main**, у полі підтвердження — **DEPLOY**, натиснути **Run workflow**.
4. Дочекатися зеленої позначки. Workflow послідовно виконає тести, збірку, перевірить маніфест, завантажить код у той самий Script ID та **оновить наявне Deployment ID**. Старе посилання `/exec` залишається чинним.
5. Відкрити CRM на ПК і телефоні під власним акаунтом; перевірити запис у Sheets. Перевірити, що сторонній акаунт не має доступу.

**Ніяких автозапусків за розкладом чи при кожному коміті немає**, щоб не публікувати неперевірений код. ШІ та токени ШІ не використовуються, `clasp` — безкоштовне програмне забезпечення. Можливі квоти Google та GitHub Actions.

## Відновлення

Якщо розгортання невдале, версія `/exec` може залишитися попередньою, але чернетковий код Apps Script уже міг змінитися. Поверніть **попередню версію** в Apps Script → **Керувати розгортаннями → Редагувати → Версія**, не створюючи нове розгортання. Для даних використовуйте окрему резервну копію таблиці. **Ніколи не видаляйте наявне розгортання** для оновлення.

## Типові проблеми

- `403` або `Apps Script API not enabled`: увімкніть Apps Script API у своєму Google-акаунті; перевірте авторизацію `clasp login`.
- `Invalid Credentials`: повторно виконайте `clasp login`, оновіть секрет `CLASPRC_JSON` без публікації його значення.
- `Unknown Script ID`: ви використали ID Google Sheets замість Script ID або інший акаунт.
- `Missing Secret`: заповніть усі три GitHub Secrets.
- `Головна гілка ще не містить новий інтерфейс`: спочатку опублікуйте Codex-зміни до `source/*` у GitHub та об'єднайте PR.
