# М2 — локальна функціональна CRM

## Обсяг

Гілка `codex/m2-crm-core` створена від актуальної `origin/main`. За завданням користувача локальні заявки включено до М2. Google OAuth-дозволи не потрібні; маніфест має порожні scopes, серверний `doGet` залишається закритим. Нових бібліотек немає.

- Клієнти: створення, редагування, послідовний незмінний номер, UUID для зв’язків, пошук, фільтри типу/статусу, сортування й сторінки по 20 записів.
- Архівування з відновленням попереднього статусу. Видалення з підтвердженням ставить `deleted_at`; залежні заявки приховуються, зв’язки не руйнуються. Фізичного очищення немає.
- Досьє організації/фізособи: контакти, напрями, географія, фінансування, досвід, компетенції й портфоліо. Журнал взаємодій лише доповнюється: редагування без аудиту не дозволено.
- Заявки: створення з досьє або реєстру, редагування бізнес-полів, зміна клієнта й статусу, м’яке видалення. Реєстр і досьє читають одне сховище. UUID, номери, часові мітки й версії керуються сервісом.
- Подані рядки жовті, відхилені сірі, робочі білі. Оцінювання, перевірка, виграно й зупинено мають власні текстові статуси; останні два показано нейтрально білими, без прирівнювання до «У роботі».
- Невідома сума залишається порожньою. Валюти EUR/UAH/USD/GBP; сортування сум спочатку розділяє валюти й не конвертує їх. Дати вводяться в ISO 8601 із часовим поясом; реєстр показує дату в Europe/Kyiv.

## Запуск і локальне збереження

Node.js 22+: `npm test`, `npm run build`, `npm start`; відкрити `http://127.0.0.1:4173`. Якщо порт зайнятий, у PowerShell: `$env:PORT='4175'`, потім `npm start`.

Потрібен сучасний браузер із localStorage та Web Locks. Запуск через HTTP на loopback; відкриття HTML через file:// не підтримується для запису. Дані живуть лише у профілі браузера на поточному origin (інший порт — інше сховище). Ключ `crm-m2-synthetic-v2`; жодних клієнтських файлів у Git. Очищення даних браузера видалить локальний набір.

Запис спочатку проходить перевірку, потім атомарний `localStorage.setItem`; лише після успіху змінюється стан у пам’яті. Помилка квоти залишає форму та старі дані. Web Locks серіалізує записи вкладок. Ревізія всього сховища й версії записів відхиляють застарілі зміни; після повідомлення про конфлікт слід зберегти текст форми окремо й оновити сторінку. Пошкоджене сховище не скидається автоматично.

## Контракт майбутнього серверного сховища

`source/server/core.js` експортує `CrmService` і `LocalRepository` для Node та локального браузера. Це незалежна від DOM бізнес-логіка, а не відкритий мережевий API.

| Інтерфейс | Призначення |
|---|---|
| `read()` | Копія стану, без посилань на внутрішні об’єкти |
| `transaction(change)` | Перевірка ревізії, зміна копії, валідація зв’язків, атомарне збереження або відмова |
| `snapshot()` / `restore(snapshot)` | Тестовий JSON-знімок та атомарне відновлення; лічильник номерів не зменшується |
| `initialize(seed)` | Початкові вигадані записи лише для порожнього набору; повтор не повертає видалені записи |
| `listClients(filters)` | Пошук, тип/статус, сортування, сторінка та ліміт (до 100); результат `items,total,page,limit` |
| `saveClient(input,id,version)` | Створення/оновлення за білим списком бізнес-полів |
| `clientAction(id,action,confirmed)` | Архів, відновлення з архіву, м’яке видалення |
| `saveApplication(input,id,version)` | Валідація та запис заявки зі зв’язком на наявного клієнта |
| `deleteApplication(id,confirmed)` | Підтверджене м’яке видалення заявки |
| `addRelated(table,input)` | Додавання контакту/взаємодії до наявного клієнта |

Генератор UUID передається в `CrmService(repository, uuid)`; майбутній Apps Script зможе передавати `Utilities.getUuid`. Адаптер Sheets має забезпечити той самий контракт під `LockService`, перевірку власника, ревізії та відновлення після часткового запису. Пряме послідовне оновлення аркушів без журналу відновлення не відповідає контракту транзакції.

Локальна модель компактна: профіль міститься в клієнті, грант/донор/дедлайн — у заявці. Під час окремо погодженого підключення Sheets потрібне відображення профілю в `client_profiles`, грантових реквізитів у `grants` зі стабільним `grant_id`, а `amount` — у `requested_amount`. Назви грантів не можна автоматично об’єднувати. Службові поля імпорту тут не редагуються, імпорту немає. Локальний адаптер читає набір повністю; для Sheets адаптер має виконувати `listClients` із пагінацією на сервері. Це межі підготовки інтерфейсів, а не реалізація Sheets.

## Перевірки

Автоматичні тести охоплюють CRUD, незмінність номерів/UUID, архів/відновлення, зв’язки, статуси, суми/дати, контакти/взаємодії, відмову застарілому запису, квоти, повторну ініціалізацію, знімок і відновлення. Попередні тести календарного адаптера в пам’яті залишено; реальна синхронізація не виконується.

Продуктивні резервні копії, Google-авторизація, Drive, Calendar, імпорт, повне приймання `ACCEPTANCE.md` та реальні клієнтські дані не входять у цей етап. М3 не запускався.

### Результат перевірок М2

- 29/29 автоматичних тестів успішні; `npm run build`, синтаксична перевірка JavaScript і `git diff --check` успішні.
- У браузері: порожня назва відхиляється; створено й змінено вигаданого клієнта з номером 0004; архівування/відновлення працює; додано контакт і взаємодію. Створена заявка прив’язана до цього досьє й видима в реєстрі після перезавантаження. Змінено суму й статус із поданого на відхилений.
- Перевірено скасування діалогу видалення, видалення заявки й клієнта та відмову застарілій вкладці після зміни даних. Для підтверджень використовується доступний HTML-діалог із початковим фокусом на «Скасувати».
- Перевірено пошук клієнта, переходи між реєстром, досьє та заявкою. На ширині 360 px реєстр, каталог, досьє й форма заявки не мають горизонтального переповнення сторінки; таблиця прокручується всередині своєї області. Перевірка виконана у браузері, не на фізичному телефоні.
- Скриншоти містять тільки синтетичні приклади: `screenshots/m2-desktop.jpg`, `screenshots/m2-mobile.jpg`.
- Реальні Google-файли, календарі й листування не створювалися та не змінювалися. Немає OAuth, зовнішніх AI-викликів, платних залежностей або розгортання.
