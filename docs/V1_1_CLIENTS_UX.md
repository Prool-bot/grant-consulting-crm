# CRM 1.1 — завершальне доопрацювання клієнтського інтерфейсу

## Зміни

- Каталог: збережено сім колонок, пошук, фільтри та пагінацію; додано «Запитувано», «Присуджено», «Найближчий дедлайн», «Остання заявка». Індекс обчислюється одним проходом по вже завантажених заявках, без додаткових RPC і запису агрегатів у базу.
- Запитувано — суми `amount`, присуджено — окремі суми `award_amount`. Кожна валюта рахується окремо, конвертації немає. Архів враховано, м’яко видалені заявки виключено. `null` не стає нулем; за відсутності сум показано «Не вказано», для частково відомих сум — явну примітку з кількістю невідомих. Присудження не підтверджує фактичного надходження коштів.
- Суми сортуються за алфавітними наборами валют (EUR, EUR/UAH, UAH тощо), далі — послідовно за числовими значеннями валют у наборі. Напрямок змінює числовий порядок усередині групи. Багатовалютні підсумки не зводяться до єдиного числа. Невідомі суми й дати завжди в кінці.
- Найближчий дедлайн — строго пізніше поточного моменту серед неархівних активних заявок, без rejected/stopped/won та невалідних дат. Якщо майбутніх немає, це прямо зазначено; прострочені дати не видаються за майбутні. Остання заявка визначається за `created_at`, із підписом «Створено», незалежно від `submission_at`.
- Картка: компактний заголовок, статус, кількість заявок, остання взаємодія, найближчий дедлайн і наявна наступна дія; невідоме — «—». «+ Заявка клієнта» залишається видимою. Архів/відновлення й видалення — у нативному меню «Дії» (Enter/Space, Tab, Escape); видалення потребує підтвердження.
- Досьє: п’ять тематичних блоків; порожні поля приховано лише в перегляді, порожній блок має кнопку редагування. Наступна дія відображається у короткому огляді, редагується тим самим полем досьє. Компетенції та портфоліо доступні для фізосіб; при зміні типу збережені значення не стираються.
- Контакти: компактні картки з посадою, телефоном, e-mail і бажаним каналом. `mailto:`/`tel:` формуються лише для перевірених значень. Додавання/редагування відкриває окрему форму, збереження повертає список. Оновлення через `saveContact` зберігає UUID, створення та інші поля, перевіряє версію; у Sheets також діють ревізія під ScriptLock та ідемпотентний UUID RPC.
- Історія: стабільний порядок від нових до старих, локальні дата й час Europe/Kyiv із переходами зимового/літнього часу. Початковий ISO із поясом зберігається точно. Журнал залишається незмінним після додавання.
- Таблиця заявок PR №6, її сім колонок, лічильники, кольори й окремі перегляд/редагування збережені.

## Перевірки

`npm test`: 76 тестів, включно з усіма попередніми 65. Нові перевірки охоплюють агрегати, валюти, невідомі суми, архів/видалення, дедлайни, сортування, досьє/огляд, Kyiv, XSS, контакти, сталі UUID, конфлікти й повтор після втраченої відповіді на синтетичному Sheets. Старі перевірки квот, резервування, відновлення та CRUD проходять.

`npm run build`, `node scripts/verify-cloud-release.js`, `git diff --check` — обов’язкові перевірки випуску. Браузерний сценарій `scripts/check-clients-ui.cjs` використовує вже доступні Playwright та Edge без нових залежностей: 1440×1000 і 360×800, меню з клавіатури, XSS контакту, приховані форми, редагування, архів/відновлення, видалення та CRUD заявок. Горизонтальне прокручування сторінки відсутнє; прокручується таблиця.

## Сумісність і обмеження

Міграцій, змін схеми/аркушів/версії бази, повторного `setupCrm_` немає. Адаптер Sheets не змінено. Нових пакетів, зовнішніх ресурсів, Google API чи OAuth-scopes немає; чинні `spreadsheets` і `userinfo.email` залишаються для сховища та перевірки власника. Локальні перевірки не використовують Google OAuth.

Позначку «основний контакт» відкладено: поточний контракт такого поля не визначає. Історія не редагується. Старі заявки без `created_at` не отримують вигаданих дат. Каталог не показує окремого лічильника прострочених заявок.

Реальні CRM_DB_TEST, Google-файли, Script Properties і розгортання не відкривалися та не змінювалися. Деплой і merge не виконувалися. Перед продуктивним випуском власником залишаються ручний огляд безпеки, перевірка Google-входу й `docs/ACCEPTANCE.md`.
