# Безпека та приватність — обов'язкові правила

1. Публічність коду: GitHub `Public`; **у репозиторії тільки код, безпечна документація та синтетичні дані**. Будь-який коміт стає загальнодоступним, а його видалення з поточного дерева не гарантує видалення з історії. Перед кожним комітом перевіряти наявність секретів і персональних даних.
2. Особиста Google-інфраструктура: виключно акаунт власника, адресу якого НЕ зберігати в публічному репозиторії; не надавати доступ акаунту ГО або стороннім особам.
3. Права Apps Script: тільки власник, мінімальні OAuth-scopes, окрема папка і календар. Заборонені публічні веброзгортання.
4. Ідентифікація: вебсесія має бути перевірена тестом входу/відмови; уникати хибних припущень про `Session.getActiveUser().getEmail()`.
5. Дані клієнтів: збирати лише потрібне, отримувати законну підставу, інформувати про обробку, обмежувати доступ, визначити строки видалення.
6. Передача даних ШІ: за замовчуванням вимкнено; тільки очищений/знеособлений текст і після підтвердження; перевірити умови обробки у провайдера.
7. Конфігурація: Script Properties; ключі поза GitHub і поза логами; локальні `.env`, `.clasprc.json`, `.clasp.json` не комітити.
8. Захист від втрати: бекап, регулярний експорт, тест відновлення, журнал помилок без секретів.
9. Gmail: не читати всю пошту за замовчуванням; жодних автоматичних листів, масових розсилок і контактів без підтвердження.
10. Перед продуктивним використанням: перевірка ролей, мобільний вхід, ліміти, вихід/втрата сеансу, резервне копіювання.

## Публічний репозиторій — додаткові перевірки
- Перед кожним `git push` перевіряти `git diff --cached`, історію змін і відсутність персональних даних/секретів у тестах, скриншотах, логах та GitHub Actions.
- Не комітити ідентифікатори реальних таблиць, папок і календарів, ключі Apps Script, особисту адресу Gmail, експорти, справжні листи, файли клієнтів чи дампи бази.
- Реальні Google-ресурси — лише у приватному Drive/Sheets/Calendar власника; проєкт Google Apps Script має бути доступний лише власнику. Публічність GitHub **не означає** публічність CRM.
- Для розгортання застосовувати локальні конфігурації і Script Properties; значення з локальних файлів не друкувати в термінал/журнали CI.
- Усі демонстрації та скриншоти в GitHub повинні містити **лише вигаданих клієнтів**.
